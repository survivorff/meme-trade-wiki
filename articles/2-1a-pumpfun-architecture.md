# Pump.fun 架构拆解：一个点燃 Meme 产业的 Solana Program

> Pump.fun 是过去两年 Web3 最赚钱的应用之一（累计收入 $10B+）。它技术上其实是个**不到 2000 行 Rust 代码的 Solana Program**。这篇拆解它的核心架构。

## 表面认知

"Pump.fun 就是一个发射台 + bonding curve，没什么技术含量。" 如果只看合约代码确实不复杂。但它的真正工程价值在**把一件事做到极致**：让任何人 10 秒内发一个 Token + 让交易成本接近零 + 让毕业过程完全自动化。

## 真实情况

### Pump.fun 的架构全貌

```
┌─────────────────────────────────────────────────────┐
│  用户层：Web UI / Telegram Bot / 第三方平台            │
└─────────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  后端 API：创建、查询、元数据                          │
│  - 创建 Token 的前端流程                              │
│  - 图片 / 描述的 IPFS 存储                            │
│  - 聚合数据展示（K 线、交易量）                        │
└─────────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  核心：Solana Program（链上合约）                     │
│  Program ID: 6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5u... │
│  - create: 创建新 Token                                │
│  - buy: 沿 bonding curve 买入                         │
│  - sell: 沿 bonding curve 卖出                        │
│  - migrate / withdraw: 毕业到 Raydium/PumpSwap        │
└─────────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  毕业后：Raydium / PumpSwap 的流动性池                │
└─────────────────────────────────────────────────────┘
```

### 核心合约（Program）结构

Pump.fun 的 Solana Program 是一个 **Anchor 框架写的 Rust 合约**。核心指令：

**1. `create`**：创建新 Token
- 创建 SPL Token Mint（标准 Solana Token 程序）
- 创建 Bonding Curve 账户（保存当前状态）
- 初始化金库（保存累积的 SOL）
- 设置 metadata（关联 IPFS 上的图片 + 描述）
- **费用**：大约 0.02 SOL（~$3-4）

**2. `buy`**：用 SOL 买入 Token
- 根据 bonding curve 公式计算当前价格
- 接受用户传入的 SOL
- 按公式转出对应数量的 Token
- 更新 bonding curve 状态
- **抽取手续费**（约 1%）进入平台金库

**3. `sell`**：卖出 Token 换 SOL
- 逆向 bonding curve 计算
- 接受用户 Token
- 转出对应 SOL
- 同样抽 1% 手续费

**4. `migrate` / `withdraw`**：毕业触发
- 达到毕业条件后自动触发
- 从 Pump.fun 账户抽取全部流动性
- 注入 Raydium 或 PumpSwap 的新池子
- 燃烧或销毁 LP Token（使用户无法撤出"新"流动性）

### Bonding Curve 的数学实现

Pump.fun 用的是**常数乘积公式**（Constant Product Formula）的变体：

```
虚拟 SOL Reserve × 虚拟 Token Reserve = k（常数）
```

初始参数（2026 年典型值，可能有调整）：
- 虚拟 SOL：**30 SOL**
- 虚拟 Token：**1,073,000,000**
- 总供应：**1,000,000,000 Token**

**定价公式**：

```
当用户买 ΔSOL 时:
  新的虚拟 SOL = 30 + ΔSOL
  新的虚拟 Token = k / (30 + ΔSOL)
  用户获得 Token = 原虚拟 Token - 新虚拟 Token
```

**特征**：
- 早期买入价格极低（$0.0001 以下）
- 随着买入，价格指数级增长
- 毕业时价格大约是初始的 **30-40 倍**

**为什么要"虚拟"储备？**

如果用真实 SOL 和 Token 作为初始储备，早期用户没有对手盘就买不到。**虚拟储备是数学意义上存在，但不是真实资金**，让第一个买家就有对手盘。

### 毕业机制的工程细节

**毕业条件**：

- Bonding Curve 累积了 **~85 SOL** 的真实 SOL（虚拟 SOL 达到 115 SOL）
- 市值约 **$69,000**（此数字随 SOL 价格波动）
- 约 **80% 的总供应被卖出**（剩 200M Token 用于迁移）

**毕业触发方式**：

- **不是自动的定时检查**，而是由**下一笔交易触发**
- 某笔 buy 使 SOL 累积达到阈值时，合约自动执行 migrate 逻辑
- 触发者不需要支付额外费用（移除流动性是合约自主行为）

**流动性迁移的两个目的地**：

历史上 Pump.fun 毕业的币都去 **Raydium V4**。2025 年后 Pump.fun 推出自家 AMM **PumpSwap**：

```
Pump.fun 毕业 → 约 50% 去 Raydium → 50% 去 PumpSwap（2025+）
```

**PumpSwap 的设计目的**：
- 截留毕业交易量（不给 Raydium）
- 向创建者分配交易费（Creator Revenue Share）
- 保持 Pump.fun 生态闭环

**流动性迁移的具体动作**：

```
Step 1: 合约从 Bonding Curve 提取累积的 SOL（~80 SOL）
Step 2: 提取剩余的 Token（200M）
Step 3: 在 Raydium/PumpSwap 创建新池子
        - 传入 ~80 SOL + 200M Token
        - 按当前毕业价定价
Step 4: 生成 LP Token（表示池子里的流动性份额）
Step 5: 销毁 LP Token（Burn）或转入不可撤回的地址
        - 这一步保证"终极流动性锁定"
        - 没人能撤出这部分 LP（包括 Pump.fun 官方）
```

这个设计是 Pump.fun 核心的**防 Rug 承诺**——毕业后的币永远有流动性。

### 抗狙击设计（和它们的失效）

Pump.fun 从 2024 年开始做过一系列抗狙击尝试：

**尝试 1：发射器延迟**

- 一开始新币创建后需要 1 个 slot（400ms）才能交易
- 狙击者的反制：**监听 `create` 事件**，提前准备 `buy` 指令

**尝试 2：首笔买入滑点限制**

- 限制第一笔买入不能超过 X SOL
- 狙击者的反制：**多钱包分散买入**，每个钱包买 X SOL

**尝试 3：捆绑检测（Bundle Detection）**

- 检测同一个钱包组的多笔交易在同一 Jito Bundle
- 有迹象则标记并可能限制
- 狙击者的反制：**跨 Bundle 拆分**

**现状**：Pump.fun 基本放弃了强制抗狙击，转为**让新币一发射就 500ms 内竞争**。

**影响**：
- 90% 的 Pump.fun 新币在**前 30 秒**就决定了命运
- 散户狙击胜率极低（< 10%）
- 专业团队垄断了首 10 秒的买入

### 手续费模型

Pump.fun 的手续费构成：

**创建费**：
- 约 0.02 SOL 一次性（~$3-4）
- 用于支付 Solana 账户租金 + IPFS 存储 + 平台收入

**交易费**：
- 每笔 Swap 抽 **1%**（进买入也是，卖出也是）
- 大部分归 Pump.fun，少部分归 Solana 网络（Priority Fee）

**毕业费**：
- 约 6 SOL（~$1000）
- 从 Bonding Curve 收集的 SOL 里扣除
- 实际迁移到 Raydium/PumpSwap 的 SOL ≈ 80 SOL

**创建者分成**（2025 年新增）：
- 毕业后 Token 在 PumpSwap 上的交易手续费
- 部分分给原始创建者（激励创建者持续推广）
- 这是 Pump.fun 吸引创建者留在自家 AMM 的钩子

### Pump.fun 后端的工程复杂度

合约只是**链上的 20%**。剩下 80% 是链下工程：

**1. 数据聚合层**
- 实时订阅所有 Pump.fun Program 的事件
- 构建每个 Token 的 K 线、交易量、持仓分布
- 搜索 / 排序（新币、热门、即将毕业）

**2. 元数据服务**
- 上传图片到 IPFS（Pinata / 自建 cluster）
- 关联 Token Mint 和元数据
- 防止图片失效（定期 pin 重要 Token）

**3. 反垃圾过滤**
- Pump.fun 每天新建 Token 数量高峰期 **10,000+**
- 80% 是垃圾（刷新、测试、恶意）
- 推荐算法要过滤掉这些

**4. 社交功能（2024 年加入）**
- Token 评论、点赞、分享
- 直播（Pump.fun 一度有 Pump.live 直播功能）
- 应对直播内容的合规压力（成人内容、仇恨言论）

**5. 防 MEV 内部工具**
- 检测恶意狙击团队
- 黑名单管理
- 监控异常 LP 操作

### Pump.fun 对 Meme 产业的系统性影响

**正面**：
- **标准化了"发币"流程**：10 秒发币 + 自动毕业
- **解决了长尾 Meme 的流动性问题**：毕业机制保证基础流动性
- **创造了巨大的产业链**：狙击工具、交易平台、数据分析、跟单 Bot 全部围绕 Pump.fun

**负面**：
- **批量刷垃圾 Token**：99% 的 Token 几分钟内归零
- **鼓励了"归零博彩"**：用户追逐每一个新发射
- **吸引了专业狙击团队**：散户几乎不可能赢

### 克隆与竞品

Pump.fun 的代码在 GitHub 上有多个 fork：

- **Four.meme**（BSC）：BSC 上的克隆，亚洲市场主导
- **LetsBonk**（Solana）：Solana 上的竞品，生态不如 Pump
- **Moonshot**（多链）：跨链发射台
- **Zora、Clanker**（Base）：和 Pump.fun 模式不完全相同，但受其启发

**为什么克隆难以颠覆**：

- 链上合约 100% 可 fork，但**生态不可 fork**
- Pump.fun 有数百万用户 + 所有 Meme 工具的默认支持
- 新发射台要解决"冷启动"问题

### 技术上学到什么

作为工程师，Pump.fun 教给行业的：

1. **极致简化 = 极致增长**：合约只有 **~2000 行**，但创造了 $10B+ 收入
2. **合约和产品的边界**：把 80% 逻辑留在链下是正确的工程选择
3. **Meme 产业的真正护城河是生态**，不是算法创新
4. **抗狙击 vs 公平发射**是不可调和的矛盾 —— Pump.fun 选了公平
5. **AMM + Launchpad 合体** 的产品范式（PumpSwap）是未来方向

## 经验教训

1. **Pump.fun 的合约简单，工程复杂**：2000 行 Rust，但支撑起一个每天 10K 新币的庞然生态
2. **Bonding Curve 的虚拟储备是数学技巧**，不是骗局 —— 是为了让第一个买家有对手盘
3. **毕业机制的"终极流动性锁定"是它最核心的信任承诺** —— 比任何合约审计报告都重要
4. **抗狙击设计失效是必然** —— 公平发射和抗狙击本质对立
5. **PumpSwap 是 Pump.fun 的"第二曲线"** —— 从一次性收费（创建）转向持续收费（交易分成）
6. **99% Meme 归零的根本原因是 Pump.fun 的设计**：低门槛 + 自动毕业 = 疯狂投机
7. **Pump.fun 的代码可以 fork，生态不可以** —— Four.meme 等克隆永远追不上
